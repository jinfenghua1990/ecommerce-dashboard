# V1.6.1 — 全新 UI 替换旧版 UI

## 本版目标

在 V1.6.0 业务能力不变的前提下，用 V1.6.1 新 UI 统一替代历史前端外壳：全系统只保留一套深色全局侧栏、独立业务路由和动态全宽工作区，不再让旧工作台、旧采购链页面或其它业务模块互相嵌套。

## 已完成的旧 UI 清理

- 正式 `/purchase/workbench` 中历史 `WorkbenchSidebar / V1.0` 源码已从主页面真实删除，不再依赖 CSS 隐藏。
- 与旧侧栏配套的 `fetchMe / logout / AuthUser` 等仅供旧壳使用的代码一并从采购页删除。
- 删除旧侧栏后专用的全局 CSS 隐藏规则，采购页仅保留业务本身布局。
- 原 `purchase/workbench-v2` 约 97KB 旧版 UI 已删除，只保留到新版采购工作台的兼容跳转。
- 原 `procurement-chain/detail` 旧版采购链详情 UI 已删除；历史 `?id=` 自动映射到新版采购订单详情。
- `/purchase`、`/procurement-workbench`、`/procurement-board`、`/procurement-ledger`、`/procurement-chain` 均已确认只保留轻量兼容跳转，不存在第二套视觉页面。
- 删除未使用的旧 `PhasePlaceholder` UI。
- 采购工作台源码与运行时都只保留 5 个采购域视图：`orders / suppliers / chain / matching / tax`。
- 销售、货品、库存、回款、利润、财务、异常、自动化、设置等正式业务页不再作为采购工作台内部 `?view=` 嵌套模块。

## 新版 UI 与布局

- 经营总览使用深色全局侧栏 + 浅色经营驾驶舱。
- 正式业务页面全部保持独立路由，不再被采购工作台统一重定向。
- 主内容区使用浏览器剩余宽度动态铺满；顶层历史 `max-width` 不再限制 1440 / 1920 / 2560 大屏。
- 宽表格只在自身横向滚动容器内滚动，不让整个业务页横向溢出。
- 首页与侧栏入口直接进入对应正式业务页面。

## 自动防回归

`npm run check:routes` 现在会阻断以下回归：

1. 侧栏链接没有真实页面。
2. 正式业务路由再次被采购工作台劫持。
3. 7 个历史采购入口重新出现完整旧 UI，而不是轻量跳转。
4. 正式采购页重新出现 `WorkbenchSidebar / SidebarLink / V1.0`。
5. 采购工作台重新嵌入销售、货品、财务、设置等正式业务页。
6. 采购工作台重新出现 5 个采购域之外的旧 `view`。

GitHub CI 前端阶段固定执行：新版 UI / 导航检查 → TypeScript → Production static build。

## 兼容策略

旧 URL 暂时保留是为了浏览器收藏、历史链接和外部入口不失效，但这些 URL 不再拥有自己的视觉界面；访问后只会进入 V1.6.1 新 UI。

## 不变内容

- 不修改真实业务数据。
- 不修改数据库结构。
- 不修改后端业务口径。
- 继续统一运行在 8000 端口。
- `release/v1.6.0` 保留为稳定回滚基线。
