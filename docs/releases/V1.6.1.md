# V1.6.1 — 全新 UI / 导航 / 动态布局

## 本版目标

在 V1.6.0 业务能力不变的前提下，用 V1.6.1 新 UI 统一替代历史前端外壳：全系统只保留一套深色全局侧栏、独立业务路由和动态全宽工作区，不再让旧工作台、旧采购链页面或其它业务模块互相嵌套。

## 主要变更

- 经营总览升级为深色侧栏 + 浅色经营驾驶舱。
- 正式业务页面保持独立路由，不再被采购工作台统一重定向。
- `/purchase/workbench` 纳入统一全局侧栏；历史第二套 `WorkbenchSidebar / V1.0` 不再作为运行时全局导航显示。
- 原 `purchase/workbench-v2` 约 97KB 旧版 UI 已删除，页面只保留到新版采购工作台的兼容跳转。
- 原 `procurement-chain/detail` 旧版采购链详情 UI 已删除，历史 `?id=` 自动映射到新版采购订单详情。
- 采购工作台运行时只开放：采购订单 / 供应商管理 / 采购链路 / SKU 匹配 / 发票对账。
- 销售、货品、库存、回款、利润、财务、异常、自动化、设置等正式业务页不再作为采购工作台内部 `?view=` 嵌套模块。
- 删除未使用的旧 `PhasePlaceholder` UI。
- 主内容区使用浏览器剩余宽度动态铺满；顶层历史 `max-width` 不再限制大屏。
- 宽表格限定在自己的横向滚动容器内，不让整个业务页被横向撑开。
- `npm run check:routes` 除验证侧栏路由外，新增旧 UI 回归阻断：旧页面必须保持轻量跳转，采购工作台不得重新嵌入其它正式业务页。
- GitHub CI 前端阶段固定执行：新版 UI / 导航检查 → TypeScript → Production static build。

## 兼容策略

旧 URL 暂时保留是为了浏览器收藏、历史链接和外部入口不失效，但这些 URL 不再拥有自己的视觉界面；访问后只会进入 V1.6.1 新 UI。

## 不变内容

- 不修改真实业务数据。
- 不修改数据库结构。
- 不修改后端业务口径。
- 继续统一运行在 8000 端口。
- `release/v1.6.0` 保留为稳定回滚基线。
